Nexus OSINT Query API Specification

Complete REST API reference and schema guide for the Nexus OSINT Data Platform. Supports keyset-paginated queries, multi-entity enrichment, lineage tracking, and complete item relation graphs.

🔒 Constant-Time Bearer Authentication: Authorization: Bearer <API_TOKEN>

Request and Response Conventions

Verified against the repository implementation on 18 October 2026. Default address: http://127.0.0.1:3000 (API_HOST / API_PORT). All /v1 routes require the exact Authorization: Bearer <API_TOKEN> header; API_TOKEN must contain at least 24 characters. Health probes are public. All documented routes use GET.

Reality-scoped requests default to realityId=0. Supply realityId=1 for simulation data. Item IDs do not replace the reality query parameter. URL-encode path identifiers and query values. Strict query schemas on items, sources, authors, entities, queries, and stats reject unknown query keys with 400. Topic-list validation strips unknown keys; handlers without query validation ignore query parameters.

Item feeds use (published_at DESC, item_id DESC) and opaque filter-scoped cursors. Keep filters (including full) unchanged between pages; limit can change. Source, author, and entity registries instead use plain identifier cursors in ascending order. Topic and collection-query lists are bounded without continuation cursors. Item time bounds require ISO-8601 timestamps with a timezone; from must precede to.

PostgreSQL bigint fields (including content_revision, simhash, snapshot_id, and engagement counts) serialize as decimal strings; SQL null stays JSON null. Timestamps are strings. Examples labeled “selected fields” are abbreviated and do not define the complete schema. Stored enrichment may be empty or null because model processing is currently inactive.

Errors: 400 {"error":"Invalid query parameters"} or a route-specific validation message; invalid/mismatched item cursors return {"error":"Invalid cursor"}. 401 {"error":"Unauthorized"}. Missing detail records return 404 with a resource-specific error. Unhandled failures return 500 {"error":"Internal server error"}. Readiness uses its separate 503 status body documented below.

💎 Enriched Item Detail Architecture

GET /v1/items/:id

Only GET /v1/items/:id resolves the core item and its related data in a repeatable-read snapshot. List endpoints with ?full=true return all selected core item fields, without joined relations. Model processing is currently inactive; enrichment fields expose stored data and may be empty or null:

📄 Core Item core.item
Native publication attributes, text, language metadata, cryptographic hashes, and observation lineage.
item_id platform native_id content_text content_hash simhash content_revision
📡 Source Identity core.source
Source channel, handle/URL, tier classification, operational arena, and subscriber statistics.
source_id arena (IL/ARAB/INTL) tier (watchlist/discovery) subscribers
👤 Author Profile core.author
Author verification state, follower counts, automated account detection, and bot credibility score.
handle verified is_automated bot_score followers
🖼️ Media Attachments core.item_media
Ordered media attachments (images, video, documents) with OCR extracts and audio transcripts.
media_type media_url duration_s ocr_text transcript
🏷️ Topics & Enrichment core.item_topic + topic
Classification topics joined with registry metadata, taxonomies, and model confidence scores.
topic_id name description score (0..1)
📍 Locations & Geotags core.item_location + entity
Extracted geographical references joined with PostGIS entities, admin areas, and GeoNames identifiers.
place_id geo_kind canonical_name country
🏢 Named Entities core.item_entity + entity
NER extractions (persons, organizations, locations) linking surface forms to canonical records.
entity_id type (PER/ORG/LOC) canonical_name surface_form
🎯 Collection Queries core.item_query_match + query
Ingestion collection queries that triggered discovery and matched this item.
query_id query_text matched_at
🤖 AI Classification core.classification
Stored classification for the current revision: relevance scoring, misinformation score, sentiment, and English summary.
relevance misinfo_score sentiment summary_en
📊 Engagement Snapshot core.engagement_snapshot
Latest captured metrics: views, likes, reposts, comments, quotes, and reactions breakdown.
views likes reposts replies reactions
🧬 Vector Embeddings core.embedding
Stored embedding metadata for the current revision. Vector values are excluded; model processing is currently inactive.
model content_revision embedded_at
🔗 Lineage & Thread Lineage Tree
Direct links to root duplicate, reply-to parent, quoted item, shared item, and immediate replies.
duplicateOf replyTo quoted replies[]

GET /v1/items/:id Get full item document with stored relations ▼

Besides core item fields (excluding tsv), the response includes media, topics, locations, entities, queries, classification, engagement, source, author, reality, platformInfo, embeddings, and relations. Topics, locations, entities, classification, and embedding metadata are limited to the current content_revision. Optional single relations are null when absent; collection relations are arrays. Relations include duplicateOf, replyTo, quoted, sharedFrom, plus up to 10 direct replies and 10 duplicates.

Returns the exhaustive representation of an item, merging document fields, source info, author stats, media attachments, topics, locations, NER entities, query matches, stored classification, engagement snapshot, embedding metadata, and thread lineage.

GET /v1/items/:id/media Get media gallery, transcripts, and OCR results ▼

Returns a bare array of media rows ordered by position. No realityId query parameter is read and the item is not checked for existence: an unknown valid ID returns []. OCR and transcript fields contain stored values only.

200 OK — Media Example (selected fields)
[
  {
    "item_id": "0:telegram:1098234",
    "position": 0,
    "media_type": "image",
    "media_url": "https://example.com/asset.jpg",
    "ocr_text": "TRANSIT COORDINATION 10-13-2026"
  }
]
GET /v1/items/:id/enrichment Get asynchronous enrichment jobs, statuses, and processor outputs ▼

Each job exposes jobType, processorVersion, eventId, contentRevision, status, attempts, nextRunAt, lastError, inputHash, result, producedAt, and diagnostic. Returns 404 if the item is absent in the requested reality.

Returns legacy enrichment jobs for the current content revision from ingest.enrichment_jobs and ingest.enrichment_results. The current silver writer persists observations without running model processors or scheduling these jobs, so {"jobs": []} is normal. Stored results are joined only for succeeded jobs with a matching input hash. Test jobs expose their output in diagnostic with result: null; other jobs have diagnostic: null.

GET /v1/items/:id/thread Get parent and child replies hierarchy ▼

Path id: 1–512 characters. Query: realityId (default 0). Returns 404 if the item is absent in that reality.

Returns {current, parent, replies}: compact item rows for the current item, nullable direct parent, and up to 50 direct replies ordered by publication time descending. This does not recursively traverse the thread.

200 OK — Thread Example (selected fields)
{
  "current": { "item_id": "it-10", "title": "Update on status" },
  "parent": { "item_id": "it-01", "title": "Initial report" },
  "replies": [
    { "item_id": "it-11", "title": "Confirmed by station 2" }
  ]
}
GET /v1/items/:id/related Get duplicates, quotes, and shares ▼

Path id: 1–512 characters. Query: realityId (default 0). Returns 404 if the item is absent in that reality.

Returns {duplicates, quotes, shares} with up to 20 compact item rows in each array, ordered by publication time descending. Each array contains direct references to the requested item.

200 OK — Lineage Map
{
  "duplicates": [],
  "quotes": [],
  "shares": []
}

Sources Registry API

GET /v1/sources List monitored channels, feeds, and accounts ▼
Query Parameters
NameTypeRequirementDescription
realityIdintegerOptionalDefault 0; range 0–2147483647. Reality 0 is operational, reality 1 is simulation.
limitintegerOptionalDefault 25; range 1–100.
platformstringOptionalPlatform code; max 50 characters.
arenastringOptionalIL, ARAB, or INTL.
tierstringOptionalwatchlist or discovery.
activebooleanOptionaltrue or false; omitted returns both active and inactive rows.
cursorstringOptionalLast returned source_id; max 1100 characters. Plain identifier, not Base64URL.

Returns {"sources": [...], "nextCursor": "..." | null}. Rows are ordered by identifier ascending; nextCursor is null when no further page exists.

List registered collection sources with filtering by arena, tier, platform, and active status.

GET /v1/sources/:id Get metadata for a specific source ▼

Path id: nonempty string, max 1100 characters. Query: realityId (default 0). Returns one unwrapped database row; 404 if absent in that reality.

Retrieves single source configuration, subscriber counts, and arena tags.

GET /v1/sources/:id/items Paginated feed of items published by this source ▼

Accepts the same query parameters and returns the same {items, nextCursor} shape as GET /v1/items. The path ID overrides the corresponding source filter. Cursors are scoped to this path ID and the supplied filters. A missing parent returns an empty feed, without a parent-existence check. Path ID: 1–1100 characters.

Cursor-paginated items feed scoped strictly to the specified source.

Realities & Sandboxes API

GET /v1/realities List simulation environments and operational realities ▼

Returns {"realities": [...]} ordered by reality_id ascending. Rows contain reality_id, name, description, and created_at. No query parameters.

Returns configured realities: Reality 0 (Operational Live) and numbered exercise sandboxes.

GET /v1/realities/:id Get single reality sandbox details ▼

Path id: integer in range 0–2147483647. Returns one unwrapped reality row; 400 for an invalid ID, 404 if absent. No query parameters.

Retrieves reality ID, name, description, and created timestamp.

Health & Probes

GET /health/live Process liveness probe (Public, unauthenticated) ▼

200 response: {"status":"ok"}.

Returns 200 OK when Node.js HTTP server is responsive.

GET /health/ready Database connectivity probe (Public, 503 on error) ▼

200 response: {"status":"ready"}. Database or schema failure: 503 with {"status":"unavailable"}.

Validates PostgreSQL database connectivity without leaking credentials or secrets on failure.
